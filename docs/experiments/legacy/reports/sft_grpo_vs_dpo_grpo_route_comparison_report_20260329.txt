MedicalGPT SFT+GRPO 与 DPO系GRPO 路径对比分析报告
生成时间: 2026-03-29

==============================
0. 报告结论先行
==============================

一句话结论:
在当前这组真实结果里，新增完成的 SFT+GRPO 并没有超过现有主线 GRPO 基线；它保住了一部分高风险分诊边界和更低的 unsafe_rate，但整体 overall_score、redflag 覆盖、actionability 仍落后于现有 DPO 系 GRPO 主线。

更精确地说:
1. “DPO 会拉低 triage_score” 这个判断，在 benchmark120 的阶段对比里依然成立。
2. 但“去掉 DPO、直接 SFT+GRPO 就会更强” 目前没有被这次实验验证。
3. 新的 SFT+GRPO 在 benchmark300 上确实比旧主线更少低估 urgent/emergency，说明它保留了更强的高风险保守性。
4. 但在更大范围上，它没有把 redflag 识别和 actionability 一起拉起来，导致 overall_score 仍低于现有主线。

当前最合理的判断不是“DPO 一定必要”，而是:
- 当前这版直接 SFT+GRPO 还不够强；
- 现有 5000-step SFT 基座偏弱；
- 当前 300-step、v1 reward 的直接 GRPO 还没把模型推到优于主线的位置。

从 benchmark120 可直接得到 3 个结论:

1. DPO 相对 SFT:
- overall_score 基本不变: -0.0005
- triage_score 明显下降: -0.0875
- triage_exact_acc 明显下降: -0.0833
- urgent_emergency_no_undertriage_rate 下降: -0.0400

- overall_score 上升: +0.0276

- urgent_emergency_no_undertriage_rate 上升: +0.1000

结论:
GRPO 的价值在于把 DPO 拉偏的临床校准重新拉回来，同时保住可操作性。

3. 因此 benchmark120 支持的不是“DPO 是终点”，而是:
- DPO 会伤 triage
- 但 GRPO 可以把它补回来，甚至超过 SFT

==============================
7. 综合判断: 这次实验到底证明了什么
==============================

一、已经被验证的结论

1. DPO 阶段确实会拉低 triage_score
- 这一点 benchmark120 已经很明确

2. 但去掉 DPO 不会自动带来更强的最终 GRPO
- 新 SFT+GRPO 没有超过当前主线

3. 新 SFT+GRPO 的真实特征是:
- 更少显式危险建议
- benchmark300 上更少低估 urgent/emergency
- 但 redflag 和记叙型 actionability 不足

4. 当前主线 DPO系GRPO 的真实优势是:
- 更完整、更像成品回答
- 红旗覆盖更好
- 可操作性更强
- 在 safety150 上整体更稳

二、为什么会这样

最可能的原因有 4 个:

1. SFT 底座偏弱
- 当前 SFT 只训练到约 0.1666 epoch
- 5000 step 更像半程 checkpoint，而不是充分收敛底座

2. 新 SFT+GRPO 的 reward 没有收好
- eval_reward 从 150 到 300 不是上升而是下降
- 说明当前 300 step 并没有把 direct-SFT route 推到最佳点

3. DPO 虽然伤 triage，但也确实给主线提供了更强的“回答组织能力”
- 这会转化成 redflag 和 actionability 优势

4. 当前比较对象是“现有最强可用主线”，不是“fresh 的干净 DPO->GRPO”
- 因此它本身已经受益于前序 GRPO 累积

三、因此不应该怎么解读

不应该解读为:
- “DPO 对最终路线一定更优”
- “SFT+GRPO 方向已经失败”

更准确的解读是:
- “当前这版 SFT+GRPO 配方还没有赢”
- “它证明 direct-SFT route 有高风险保守性的潜力”
- “但还需要更强 base 或更好的训练停止点”


==============================
8. 下一步实验建议
==============================

优先级 1:
做“更强 SFT checkpoint -> 直接 GRPO”
- 当前 direct-SFT route 用的是 5000-step SFT
- 最值得验证的是:
  - SFT 7000
  - SFT 10000
  - SFT 15000
- 每个 checkpoint 先跑小规模 benchmark，再决定是否接 GRPO

优先级 2:
回看新 SFT+GRPO 的 checkpoint-100 / 200 / 300
- 因为训练内 eval_reward 在 300 时不升反降
- 很可能 100 或 200 步比 300 更好
- 当前最需要排查的是“是不是后半程在伤 triage 稳定性”

优先级 3:
补一组真正干净的 fresh DPO->GRPO
- 本次对照对象是旧主线，不是 fresh 基线
- 如果要真正回答“DPO 是否必要”，必须有:
  - clean SFT->GRPO
  - clean SFT->DPO->GRPO
  - 同一 reward、同一步数、同一 benchmark

优先级 4:
针对 direct-SFT route 调 reward / data
- 当前短板主要在 redflag 与 actionability
- 可以优先检查:
  - actionability 权重是否偏低
  - GRPO 训练集里低风险/门诊型样本是否不足
  - must_mentions / preferred_actions 对低风险场景是否覆盖不足


==============================
9. 最终结论
==============================

如果问题是:
“现在已经完成的 SFT+GRPO，能否证明直接绕过 DPO 更好？”

答案是:
不能。

如果问题是:
“这次实验有没有价值？”

答案是:
有，而且价值很明确。

它证明了 3 件事:
1. 直接 SFT+GRPO 不是走不通，它在 benchmark300 的高风险不过度漏诊上有潜力。
2. 但按当前 5000-step SFT 基座 + 300-step v1 reward，这条路线还没有超过现有主线。
3. 下一步真正该做的，不是回到“只看 DPO 是否伤 triage”，而是验证:
   更强 SFT 底座下的 direct-GRPO，能不能同时把 triage、redflag、actionability 拉起来。

本次实证结论可以压缩成一句:
当前 direct SFT+GRPO 比主线更保守，但还不够强；主线 DPO系GRPO 仍是当前综合表现更好的成品路线。
